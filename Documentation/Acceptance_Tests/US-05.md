## AT-US05-01: Keyword search and combined filters show the exact matching count

**Links:** US-05 #5; tasks #38, #39, #40, #41.

**Given** open jobs include a Software Engineer in Montreal in Software
Engineering, a Software Intern in Toronto in Software Engineering, and a Data
Engineer in Montreal in Data & Analytics; and a closed Software Architect in
Montreal also exists.

**When** a visitor opens Find jobs, enters `  SOFTWARE  `, enters `montreal`,
selects Software Engineering, and runs the search.

**Then** only Software Engineer appears, the result count is exactly 1, and the
closed posting is excluded. Keyword, location, and category are represented in
the URL and removable active criteria. Refresh preserves the same result.

**And** removing location retains keyword/category, while Clear all restores all
open jobs.

**Automated evidence:** `test/jobs.test.js` covers matching, normalization, AND
semantics, availability, and count. Browser review covers controls, URL state,
removal, and reload.

## AT-US05-02: Job details load directly and preserve the previous search

**Links:** US-05 #5; tasks #37, #40, #41, #73.

**Given** a visitor has searched using keyword, location, and category and sees
a matching job posting.

**When** they open the job's title or View details area.

**Then** a dedicated job URL displays the correct title, company, location,
category, posting date, and complete stored description. Opening or reloading
that URL independently still loads the job.

**And** Back to jobs restores the previous criteria and matching results.
Browser Back also restores the prior search. A missing or closed job displays a
clear not-found state with a working return link.

**Automated evidence:** detail API, invalid/closed IDs, and direct HTML routes in
`test/jobs.test.js`. Browser review covers full details, reload, contextual return,
and browser Back.

## AT-US05-03: Empty results and unavailable service recover clearly

**Links:** US-05 #5; tasks #39, #40, #41.

**Given** no open job matches the chosen keyword/location/category combination.

**When** the visitor runs that search.

**Then** the count is 0, a helpful no-results message is shown, and Clear filters
restores the available postings. An empty result is not reported as an error.

**And** if the API becomes unavailable, the interface displays a separate error
with Try again and preserves applied criteria. After the service recovers,
retry restores the correct results without requiring criteria to be re-entered.

**Evidence:** empty-result and safe-error API tests; browser verification of
empty recovery and an actual stopped/restarted local server.

## AT-US05-04: Educational catalog and structured job details

**Given** an explicitly seeded development database contains the 50 managed demo
postings, using real company names only as educational context.

**When** a visitor searches `AI`, or combines `intern`, Montreal and Data & Analytics.

**Then** the sample catalog returns 7 and 2 matching jobs respectively. A global
notice explains that these are not verified live openings. Opening a result
shows overview, role-specific responsibility/qualification/preferred-skill lists,
company context and available employment/workplace/experience metadata.

**And** Apply now is disabled with a visible reason, and no application is written.
Details have one H1, semantic lists, keyboard focus, a desktop sticky summary and
a stacked narrow layout in both public and workspace contexts.

**And** a normal seed rerun creates no duplicates and preserves edits. An explicit
`--refresh` upgrades only managed demo content, preserving IDs, status and unrelated
postings. Legacy plain-text jobs remain readable after the additive migration.

**Evidence:** catalog, search, refresh and legacy-migration integration tests;
six-width browser review documented in `Documentation/US-05_Refinement.md`.
