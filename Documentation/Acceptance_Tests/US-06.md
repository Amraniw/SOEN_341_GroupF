# US-06 acceptance scenarios — Job application submission

These scenarios are ready to copy into linked GitHub acceptance-test issues.
Suggested labels: `acceptance-test`, `Sprint 2`, `US-06`.

## AT-US06-01: Signed-in job seeker submits an application successfully

**Given** a job seeker is signed in and opens an available job posting they
have not applied for.

**When** they select **Apply now**.

**Then** CareerConnect stores one application linked to that user and job with
the initial status **Applied**, displays an immediate **Application submitted**
confirmation, and provides a link to track it in the workspace.

**And** refreshing the job page replaces Apply now with **Already applied** and
the persisted current status.

**Automated evidence:** `test/applications.test.js` verifies authentication,
persistence, initial status, confirmation response, history creation, and job
lookup after submission.

## AT-US06-02: Duplicate, invalid, and unavailable submissions are prevented

**Given** a job seeker has already applied to a job, or a job is closed or does
not exist.

**When** an application is submitted for that posting.

**Then** CareerConnect creates no additional application and returns a clear,
safe explanation. A user cannot choose a status or submit unsupported fields.

**And** another job seeker may independently apply to the same available job.

**Automated evidence:** duplicate uniqueness, validation, closed/missing job,
unsupported fields, and user-isolation cases in `test/applications.test.js`.
