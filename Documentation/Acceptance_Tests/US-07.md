# US-07 acceptance scenarios — Application status tracking

These scenarios are ready to copy into linked GitHub acceptance-test issues.
Suggested labels: `acceptance-test`, `Sprint 2`, `US-07`.

## AT-US07-01: Job seeker sees current statuses in one private dashboard

**Given** a signed-in job seeker has submitted applications in different
states.

**When** they open **Applications** from the workspace.

**Then** the page displays only their applications, the current status of each,
totals for Applied, Under Review, Interview, Offered, and Rejected, and a filter
for those five statuses.

**And** each card identifies the job, company, location, application date,
latest update, progress, and a working link back to the job.

**Automated evidence:** private list, canonical status metadata, job data, and
cross-user isolation in `test/applications.test.js`; browser verification covers
the dashboard and status filter presentation.

## AT-US07-02: Status changes persist and retain a history

**Given** an application's status changes through the hiring process.

**When** the job seeker reloads the Applications workspace or signs in later.

**Then** the newest status and update time are restored from SQLite, and the
interface updates its summary and progress presentation.

**And** CareerConnect accepts only Applied, Under Review, Interview, Offered,
or Rejected and retains each transition in chronological history.

**Automated evidence:** all five transitions, labels, database constraints, and
history ordering in `test/applications.test.js`; browser verification covers an
Applied-to-Under-Review transition in both light and dark modes.
